### 详细描述（可整段粘贴）

```
【这是什么】

一个完全离线的 Shopify 店铺分析工具。打开任意 Shopify 店铺，点一下工具栏图标，
右侧面板就会告诉你这家店是怎么搭起来的、在卖什么、最近有什么变化。

所有计算都在你自己的电脑上完成，不向任何服务器发送数据。

【能看什么】

◆ 主题识别
   主题名、厂商、免费还是付费，以及"是否基于官方主题二次开发"。
   用主题的 schema 标识判定，商家改了主题名也不影响判断。

◆ 已装应用
   超过 100 条应用指纹，按分类列出这家店装了哪些第三方工具（评论、弹窗、
   客服、物流、代发、支付分期……）。每条都附上触发它的原文片段，可自行核对。

◆ 追踪像素
   区分广告像素（Meta / TikTok / Google Ads / Pinterest 等）、分析工具与营销自动化。
   有广告像素 = 这家店在投付费流量。

◆ 销量排行榜
   直接读店铺自己的畅销排序 —— 这是商家后台认可的真实销量顺序，不是估算。

◆ 店铺变化
   你每扫一次，工具就记下这家店当时的样子；下次再扫，两张一比就知道变了什么：
   卖光了 / 补货了 / 上了新品 / 下架了 / 改价了 / 排名升降 / 装了新应用。
   还能看到上新速度曲线、哪些款卖断货了、最近铺了什么新品。

◆ 选品打分
   五个维度加权给每个产品打分，点开可以看它为什么得这个分。

◆ 导出
   产品库 / 应用 / 像素 / 合集 / 店铺变化 五种 CSV，以及完整报告 JSON。
   CSV 带 UTF-8 BOM，Excel 直接打开不乱码。

【先说清楚：看不到别人的订单】

Shopify 不公开订单接口，任何浏览器插件都拿不到真实订单数据。
"店铺变化"给的是从公开信号重建的成交线索，每条都标了确定程度。
界面上也写明了：卖光不等于一定是被买走的，排名上升也不等于一定有人买。

【隐私】

· 完全离线：不向任何服务器发送数据，断网也能用
· 只用 activeTab 权限：只在你主动点图标时才读取当前标签页
· 不记录浏览历史，不读取你没点的标签页
· Cookie 只读名字不读值
· 所有数据存在本机，卸载即清除

【遇到问题】

QQ 1611744064 —— 负责调整 BUG，也是新版本发布的第一通知号。
```

## 三、权限理由（审核必看，逐条填）

商城会让你解释每个权限，照抄即可：

| 权限 | 填写理由 |
|---|---|
| `activeTab` | 用户点击扩展图标时读取**当前这一个**标签页，用于分析该 Shopify 店铺。刻意用它替代 `<all_urls>`，避免申请全网访问权限。 |
| `scripting` | 向当前标签页注入只读的采集脚本，读取店铺页面上公开可见的主题信息、脚本地址与追踪像素标识。脚本源码在 `lib/injected.js`，不修改页面内容。 |
| `storage` | 在本机保存用户设置、收藏的店铺、扫描历史和"店铺变化"所需的对比记录。数据不出本机。 |
| `sidePanel` | 在浏览器右侧显示操作面板（扩展的主要界面）。 |
| `downloads` | 把分析结果导出为 CSV / JSON 文件保存到本地。 |

**关键点**：本扩展**没有申请任何 `host_permissions`**。这是审核友好度最高的一种写法，
填表时可以主动强调这一点。

## 四、数据使用披露（逐项照选）

商城的「数据使用」表单，按以下选择：

| 问题 | 选择 |
|---|---|
| 是否收集或使用个人身份信息？ | **否** |
| 是否收集健康信息？ | 否 |
| 是否收集财务和付款信息？ | 否 |
| 是否收集身份验证信息？ | 否 |
| 是否收集个人通信？ | 否 |
| 是否收集位置信息？ | 否 |
| 是否收集网络历史记录？ | **否** |
| 是否收集用户活动？ | **否** |
| 是否收集网站内容？ | **否**（本地读取、不传输、不存储到远端，符合"不收集"定义） |
| 是否向第三方出售或转让用户数据？ | 否 |
| 是否将数据用于与核心功能无关的用途？ | 否 |
| 是否将数据用于判定信用度或放贷？ | 否 |

> **一旦勾选"收集"，就必须提供隐私政策 URL 并且披露加密方式**。
> 本扩展确实不收集，所以如实选"否"是正确且省事的做法。

## 五、隐私政策

即使不收集数据，商城也允许（并建议）提供一份隐私政策。
现成文本见 `store/隐私政策.md`，把它放到任意可公开访问的网页上，把链接填进商城即可。

> 没有网站怎么办：可以把内容发到 GitHub Gist、Notion 公开页、或者任意静态托管，
> **只要能打开就行**。链接打不开会被审核卡住。

## 七、提交步骤

1. `node tools/package.mjs` → 产出 `dist/shopify-scout-cn-v1.0.0.zip`
2. `node tools/store-assets.mjs` → 产出 `store/` 下全部图片
3. 开发者控制台 → **新增项目** → 上传 ZIP
4. 按上面第二节填商品信息，第三节填权限理由，第四节填数据使用
5. 上传图片素材
6. 提交审核

审核通常 **1–3 个工作日**。首次发布可能稍久。

## 八、可能被驳回的点，以及本包为什么不会

| 常见驳回原因 | 本包的情况 |
|---|---|
| 含远程代码 | ✅ 已扫描，无 `eval`、无 `new Function`、无远程脚本引用（`tools/package.mjs` 会逐条检查） |
| 权限过宽 | ✅ 零 `host_permissions`，只用 `activeTab` |
| 单一用途不清晰 | ✅ 只做一件事：分析当前打开的 Shopify 店铺 |
| 名称含误导性关键词 | ✅ 没蹭 "Shopify" 官方名义，名称里带了自己的品牌名 |
| 简介与实际功能不符 | ✅ 简介里承诺的五项都在界面里有对应入口 |
| 上传的包里带了开发文件 | ✅ 打包脚本只收 16 个运行时文件，`test/`、`tools/`、`docs/` 全部排除 |
| 隐私政策链接打不开 | ⚠ 需要你自己托管，**这条最容易翻车，上传前务必点开确认** |
| 截图与实物不符 | ✅ 全部是真实界面截图 |

## 九、版本更新（以后）

1. 改 `shopify-scout-cn/manifest.json` 里的 `version`（如 `1.0.0` → `1.0.1`）
2. `node tools/package.mjs`
3. 控制台 → 该项目的「软件包」→ 上传新 ZIP → 提交

**每次更新只需重传 ZIP**，商品信息与素材不用重填。
